13.作者意外将LLM记忆机制做成了程式分析系统

作者长期使用LLM代理程式协助漏洞研究,发现调查时间一拉长,模型就会遗忘先前已排除的方向,或在某项假设已被推翻后,仍继续依据它推理下去,造成结论失真。一般的记忆系统只会储存并检索旧的对话或观察纪录,但作者认为重点不该是让模型记得「说过什么」,而是要维护「目前已知的事实」是否仍然成立。他发现这与程式分析领域的做法高度相似——分析程式时会建立一组事实与推导规则,并能在某个输入事实改变时,只更新受影响的结论,而不必从头重算。基于这个类比,作者最终写出了一套供LLM使用的Datalog推论引擎,让调查过程中的事实与结论能像程式分析一样自动维护一致性,当某个前提被推翻时,相关结论也会自动失效,而不需要模型自行重建整份调查记录。

20.Amazon SageMaker Feature Store 新增批次寫入與記錄查詢功能

Amazon SageMaker Feature Store 是用來儲存與管理機器學習模型特徵的全託管服務，支援即時推論的線上服務與歷史訓練資料的離線儲存。過去團隊面臨兩大痛點：一是高吞吐量管線須逐筆呼叫 PutRecord 寫入單一特徵記錄，例如每秒處理一萬筆記錄、橫跨五個特徵群組的詐欺偵測管線，須撐住每秒五萬次個別 API 呼叫，造成連線負擔與吞吐量不佳；二是使用 In-Memory 儲存層的團隊無法瀏覽或列舉線上儲存的記錄，一旦記錄識別碼因錯誤或管線故障遺失，該記錄便永久無法復原，因為 In-Memory 層沒有離線儲存可供備援，也無法用 Athena 查詢或其他 API 尋回。AWS 宣布推出兩個新 API：BatchWriteRecord 可在單次呼叫中跨多個特徵群組寫入最多 25 筆記錄，具備部分成功語意、逐筆存活時間（TTL）控制，並維持與 PutRecord 相同的 EventTime 排序保證；ListRecords 則可分頁列舉特徵群組內的記錄識別碼，同時支援以 DynamoDB 為基礎的 Standard 層與以 Redis 為基礎的 In-Memory 層。文章並提供程式範例說明如何開始使用這兩個新 API。
